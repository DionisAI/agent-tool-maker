# ATM 0.2 架构

```text
宿主 Agent / 人类终端
        │ Skill + JSON CLI
        ▼
目录查询 / 输入 schema / dry-run / 权限声明
        │
        ├─ Maker：起草 → 规范校验 → 摘要批准 → 本地安装
        │                  └─ 1–20 步组合工具
        ▼
SQLite 任务认领 / 请求键 / 定义摘要 / 子任务引用
        │
        ├─ 原有媒体 API（队列/下载/基本验收）
        ├─ 声明式 REST（固定 origin + 凭证注入 + JSON 响应）
        ├─ 声明式 CLI（已绑定程序 + argv + 有限输出）
        ├─ MCP（发现 / schema / 白名单 / 同会话批次）
        └─ 浏览器 / 桌面 / 人工交接（明确挂起）
        │
        ▼
产物 / 哈希 / 来源声明 / 验证等级 / 未知费用
```

## 数据模型

`settings` 保存本地工具、CLI 绑定、MCP 配置、origin 和非秘密元数据。`secrets` 只存 AES-GCM 密文。`jobs` 保存参数、工作目录、请求指纹、状态与结果。`events` 仅存任务 ID、事件类型、时间。

任务参数、API 结果、图文与工程文件不是全盘加密。用户应选择受控状态目录和项目目录，不把 token 手工塞进输入 JSON。凭证引用和权限不是可转售供应商能力的法律授权。

## 幂等与不确定提交

本地 `BEGIN IMMEDIATE` 认领 request-key。重复同键同定义返回原任务；同键改输入/工作目录/新动作定义会冲突。供应商有 idempotency header 时使用本地 job-id，但不虚构端到端 exactly-once。调用中断会保留不确定状态，不盲目重发。

组合工具的子键固定为 `parent-job-id:step-name`。恢复时重新查询既有子任务，而不是创建同义新调用。并行父恢复中的步骤认领仍由 SQLite 防止重复发起。此版本不支持嵌套流程、分支、循环、事务回滚或常驻调度。

## 适配器并不统一抹平供应商参数

有界动作各自保留 schema。`implementation=native` 只表示存在执行代码。`completed` 的含义取决于动作：请求响应、CLI 退出、有限格式校验或人工文件声明。异步提交命令的后续完成/发布可见性应由显式下一步验证。

MCP 分为固定七组目录入口与通用 transport。服务器实际工具名必须发现并加入确切白名单；不会根据品牌名推断一组函数存在。缺少 OAuth/elicitation 等能力会直接拒绝，而非假成功。

## 本版刻意不承担

Agent 的通用推理、上游工具安装与许可证、托管电脑、未经授权的网页登录、强同用户进程隔离、付款网络、统一硬预算、应用商店审批、物理样品验收。所有差距见 ROADMAP。
